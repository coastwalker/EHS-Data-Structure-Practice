          Wolves Unit 2 Reference Guide
        
        

          📚 Eastlake HS Unit 2 Data Structures Study Guide & Cheat Sheet
        

        

          Everything you need for the Unit 2 Celebration: Abstract Data Types (ADTs), LIFO vs. FIFO, Eastlake custom Stack & Queue classes, Python dict & set methods, and the Maze Adventure BFS Queue-of-Stacks algorithm.
        

      

    


    
    

      

        
1. Abstract Data Types (ADTs) vs. Atomic Types

        
    
          
  • Abstract Data Type (ADT): Defined by its behavior (what operations it supports) rather than its underlying implementation. Provides simplicity and flexibility.
    • 
          
  • Atomic Data Types: Basic building blocks like int, float, bool, char combined to construct larger collections.
    • 
        

      


      

        
2. Ordered Collection Types (Stacks & Queues)

        
    
          
  • Order Matters: Items are stored and processed based on the exact sequence of arrival/insertion.
    • 
          
  • Stack (LIFO — Last In, First Out): Like a stack of plates or the function call stack. Last pushed is first popped.
    • 
          
  • Queue (FIFO — First In, First Out): Like a line at a store or print queue. First enqueued is first dequeued.
    • 
        

      


      

        
3. Associative / "Unordered" Types (Maps & Sets)

        
    
          
  • Focus on Associations & Membership: Not concerned with index position.
    • 
          
  • Map / Dictionary (dict): Associates unique keys with values. Duplicate keys overwrite old values.
    • 
          
  • Set (set): Unordered collection of unique items (no duplicates allowed) for fast in / not in membership checks.
    • 
        

      

    


    
    


      
      

        

          
A. Stacks (LIFO — Last In, First Out)

          Lesson 1
        

        

          Common Use Cases: Reversing data order, symmetric pattern matching (palindromes, balanced parentheses {[()]}), Undo/Redo history, RPN postfix evaluation, and the Function Call Stack (infinite recursion causes Stack Overflow).
        

        

          

            
              

                Custom `Stack` Method
                Underlying `list` Implementation
                Behavior
              

            
            
              

                s.push(item)
                self._items.append(item)
                Adds `item` to the top of the stack.
              

              

                s.pop()
                self._items.pop()
                Removes & returns the top item.
              

              

                s.peek()
                self._items[len(self._items) - 1]
                Returns top item without removing it.
              

              

                s.is_empty()
                len(self._items) == 0
                Returns `True` if stack has 0 items.
              

              

                s.clear()
                self._items.clear()
                Removes all items from the stack.
              

            
          

        

      


      
      

        

          
B. Queues (FIFO — First In, First Out)

          Lesson 2
        

        

          Common Use Cases: Call centers, online order fulfillment, printer queues, turn-based card games (War), and Breadth-First Search (BFS) level-by-level shortest path exploration.
        

        

          

            
              

                Custom `Queue` Method
                Underlying `list` Implementation
                Behavior
              

            
            
              

                q.enqueue(item)
                self._items.append(item)
                Adds `item` to the back of the line.
              

              

                q.dequeue()
                self._items.pop(0)
                Removes & returns front item.
              

              

                q.peek()
                self._items[0]
                Returns front item without removing it.
              

              

                q.is_empty()
                len(self._items) == 0
                Returns `True` if queue is empty.
              

              

                q.clear()
                self._items.clear()
                Empties the queue.
              

            
          

        

      


      
      

        

          
C. Maps / Dictionaries (`dict` — Key-Value Pairs)

          Lesson 3
        

        
    
          
  • Initialize: d = {} or d = dict() or d = {"samus": "867-5309"}
    • 
          
  • Safe Access (Preferred!): d.get("mario") returns None (or a custom default like d.get("mario", "UNKNOWN")) if missing, whereas d["mario"] raises a KeyError!
    • 
          
  • Add / Update vs. Non-Overwriting Insert:
            
    • d["zelda"] = "432-8789" overwrites any existing value for "zelda".
            
    • d.setdefault("zelda", "432-8789") ONLY sets the key if it does not already exist in d!
          
    • 
          
  • Remove: d.pop("pikachu", default_val) (returns deleted value or default_val) or del d["pikachu"].
    • 
          
  • Efficient Iteration: Use for key, val in d.items(): to access both key and value without redundant lookups.
    • 
        

      


      
      

        

          
D. Sets (`set` — Unique Membership & Algebra)

          Lesson 4
        

        
    
          
  • Empty Set Trap: s = set() creates an empty set ({} creates an empty dict!). Non-empty: s = {"Pizza", "Wings"}.
    • 
          
  • Add Single vs. Multiple: s.add("Fries") (one item) vs. s.update(["Tacos", "Burger"]) (all items from an iterable).
    • 
          
  • Safe Remove: s.discard("Pizza") does nothing if missing; s.remove("Pizza") throws a KeyError if missing!
    • 
          
  • Set Mathematical Operations:
            
    • Intersection (in BOTH): set1 & set2 or set1.intersection(set2)
            
    • Difference (in set1, NOT set2): set1 - set2 or set1.difference(set2)
            
    • Union (in EITHER set combined): set1 | set2 or set1.union(set2)
          
    • 
        

      

    


    
    

      

        

          3. Unit 2 Capstone Architecture: Maze Adventure Shortest Path (BFS with Queue of Stacks)
        

        
          Lesson 5 Project
        
      

      

        

          

            Why Breadth-First Search (BFS)? Unlike Depth-First Search (DFS), BFS explores rooms level-by-level using a Queue, which guarantees the first path to reach end is the shortest path!
          

          
    
            
  • Maze Representation: A dict[str, MazeRoom] mapping each room name to its MazeRoom(adjacent_rooms, keys, locked) object.
    • 
            
  • Queue of Stacks: The BFS Queue holds Stack objects. Each Stack represents a path of room names from start (bottom) to the current room (path.peek() at the top).
    • 
            
  • Why deepcopy(path) is Critical: Before pushing a neighbor onto a path, you MUST make a deepcopy so branching paths don't mutate the same Stack reference!
    • 
            
  • Locked Rooms & Keys: Visiting a room collects room.keys. A locked room can only be entered once its room name is in your collected keys set!
    • 
          

        

        

          
# Standard Unit 2 BFS Queue-of-Stacks Template (Unlocked Rooms)
def solve_simple_maze(maze: dict, start: str, end: str):
    paths = Queue()
    initial_path = Stack()
    initial_path.push(start)
    paths.enqueue(initial_path)
    visited = {start} # Set of visited room names

    while not paths.is_empty():
        current_path = paths.dequeue()
        current_room = current_path.peek()

        if current_room == end:
            return current_path.to_list() # Found shortest path!

        for neighbor in maze[current_room].adjacent_rooms:
            if neighbor not in visited and not maze[neighbor].locked:
                visited.add(neighbor)
                next_path = deepcopy(current_path) # CRITICAL: copy before pushing!
                next_path.push(neighbor)
                paths.enqueue(next_path)
    return None
