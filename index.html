1. Side-by-Side Java vs. Python 3 Syntax & Conventions

        Filterable Reference Table
      

      

        

          
            

              Topic / Concept
              Java (AP CSA)
              Python 3 (Eastlake Data Structures)
            

          
          
            

              Execution & Typing
              Compiled beforehand; statically typed (String s = "Hi";).
              Interpreted line-by-line at runtime; dynamically typed (s = "Hi"). Optional type hints (s: str = "Hi") are ignored at runtime.
            

            

              Naming Conventions
              camelCaseVars, printValues(), UpperCamelClass
              lower_snake_case for variables, functions, and methods (print_values). UpperCamelCase for classes (SugarCookie).
            

            

              Scope, Blocks & Empty Stubs
              if (x > 0) { ... } // semicolons ;
              Colon : + 4-space indentation defines scope (no { } or ;). Use pass for empty functions/classes.
            

            

              Booleans, Null & Logic
              true, false, null, &&, ||, !, else if
              True, False, None, and, or, not, elif
            

            

              String Comparison & Formatting
              name.equals("Jo")
"Item " + i		
              Compare with name == "Jo". For + concatenation, cast non-strings with str(i), or use f-strings: f"Item {i}".
            

            

              String Slicing & Division
              word.substring(0, 3)
int d = 7 / 2; // 3		
              Slice: word[0:3] (end not inclusive).
/ is float division (3.5); // is integer floor division (3).		
            

            

              Loops & `range(start, stop, step)`
              for (int i = list.length - 1; i >= 0; i -= 2)
              for i in range(len(my_list) - 1, -1, -2):
All Python for loops are for-each loops (for book in books:).		
            

            

              Lists (`append`, `pop`, `remove`, `index`)
              list.add(x); list.remove(idx); list.indexOf(x);
              lst.append(x), lst.pop(idx) (by index!), lst.remove(val) (first match by value!), lst.index(val), len(lst).
            

            

              List Comprehension & `random`
              new Random().nextInt(4);
              Comprehension: [w for w in words if "a" in w]
Random: random.randrange(0, len(words)) (end not inclusive).		
            

            

              Functions & Default Params
              Method overloading (multiple methods with same name)
              No function overloading! Use default parameter values instead: def make_greeting(name: str = "", age: int = 16) -> str:
            

            

              Classes, `__init__` & `self`
              public Dessert(String f) { this.flavor = f; }
new Dessert("Vanilla");		
              One constructor def __init__(self, f: str): self._flavor = f. Every method MUST take self first. Instantiate without new: Dessert("Vanilla").
            

            

              Inheritance & Privacy (`_x` vs `__x`)
              class SugarCookie extends Dessert { super(f, c); }
              class SugarCookie(Dessert): and super().__init__(f, c) (do NOT pass self to super()!). _var = protected convention; __var = name-mangled private (inaccessible to child class).
            

          
        

      

    


    
    

      

        
2. VS Code Debugger Controls (U1L4)

        
    
          
  • Breakpoint (Red Dot): Pauses program execution at that exact line so you can inspect local variables.
    • 
          
  • Continue (▶): Resumes running normally until the next breakpoint is hit.
    • 
          
  • Step Over (⤵): Executes the current line of code without stepping inside functions called on that line.
    • 
          
  • Step Into (↓): Enters inside the function called on the current line to debug it line-by-line.
    • 
          
  • Restart / Stop: Restarts or terminates the debugging session.
    • 
        

      


      

        
3. `unittest` & Test Case Design (U1L4)

        
    
          
  • Why Automated Tests? Prevents new code changes from breaking existing working features (regression testing).
    • 
          
  • Test Techniques: Positive (Happy Path) vs. Negative tests, Equivalence Classes (e.g. lowercase vs uppercase), Boundary Cases (index `0`, last index, 1 past end like `"find"` in `"Muffin"`), and Code Coverage.
    • 
          
  • `unittest.TestCase` Rules: Test methods MUST start with test_ and use self.assertEqual(a, b), self.assertTrue(x), self.assertFalse(x), self.assertIn(a, b).
    • 
        

      


      

        
4. Code Reviews (TAG) & Git Workflow

        
    
          
  • Why Code Reviews? Catch bugs early, share knowledge across the team, improve readability/maintainability, and optimize performance.
    • 
          
  • The TAG Model:
            
    • T — Tell something you liked about the code.
            
    • A — Ask a thoughtful question about design or logic.
            
    • G — Give a constructive suggestion for improvement.
          
    • 
          
  • VS Code Git Sync: Write commit message → Click Commit (✓) (saves to local repo) → Click Sync Changes (pushes to GitHub).
    •
