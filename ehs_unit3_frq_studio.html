Deck 1: Complexity & Big-O Analysis

          1 - Complexity and Big-O
        

        
    
          
  • Primitive Operations (1 step each): Variable assignment, function call, arithmetic, comparison, list indexing, return.
    • 
          
  • Worst-Case As n → ∞: Drop constant multipliers and lower-order terms (e.g., 6n + 5 → O(n); 43n³ + 7n log n + 70 → O(n³)).
    • 
          
  • Efficiency Hierarchy (Best to Worst):
    
            O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n^k) < O(a^n) < O(n!)
          
    • 
          
  • Hidden Loop Trap: my_list.insert(0, 1) inside for i in range(n) is O(n²), NOT O(n), because .insert(0, val) shifts all elements in O(n) time!
    • 
          
  • Independent Variables: Nested loops over range(a) and range(b) run in O(a · b); calling binary_search(list_of_size_n) inside for i in range(m) runs in O(m log n).
    • 
        

      


      
      

        

          
Deck 2: Core Recursion & Divide-and-Conquer

          2 - Recursion 1
        

        
    
          
  • The "3 Musts" of Recursion: (1) Must cover all valid inputs, (2) Must have a base case with no recursive call, (3) Recursive calls must move toward the base case on a smaller/simpler instance.
    • 
          
  • Call-Stack Unwinding Trace: mystery(11) prints 11, 6, 1, -4 going down, then unwinds printing 1, 6, 11.
    • 
        

        
def faster_power(x, n): # O(log n) Divide & Conquer
    if n == 0: return 1
    elif n % 2 == 1: return x * faster_power(x, n - 1)
    else:
        half_pow = faster_power(x, n // 2) # Compute ONCE!
        return half_pow * half_pow

      


      
      

        

          
Deck 3: Inclusion/Exclusion & String Slicing

          3 - Recursion 2
        

        
    
          
  • Palindrome String Slicing: Base case len(s) <= 1 returns True. Recursive step checks s[0] == s[-1] and recurses on s[1:-1].
    • 
          
  • Inclusion/Exclusion Pattern (Style 1 — Set Copying): Subdivide into two branches: one that excludes the removed item (target) and one that includes it (target - item).
    • 
        

        
def subset_sum_exists(num_set: Set[int], target: int) -> bool:
    if len(num_set) == 0:
        return target == 0
    smaller_set = set(num_set)
    item = smaller_set.pop()
    return (subset_sum_exists(smaller_set, target) or
            subset_sum_exists(smaller_set, target - item))

      


      
      

        

          
Deck 4: Backtracking — Choose, Explore, Unchoose

          4 - Backtracking 1
        

        
    
          
  • Core DFS Backtracking Template: For each option: CHOOSE (mutate state / mark visited / pop), EXPLORE (recurse), UNCHOOSE (restore state / unmark / add back).
    • 
          
  • Assignments: Rat_maze.py (2D grid DFS with '@' visited markers) and Queens.py (row-by-row N-Queens placement).
    • 
        

        
def subset_sum_exists(numbers: Set[int], target: int) -> bool:
    if len(numbers) == 0:
        return target == 0
    num = numbers.pop() # Choose (in-place)
    sum_exists = (subset_sum_exists(numbers, target) or
                  subset_sum_exists(numbers, target - num)) # Explore
    numbers.add(num)    # Unchoose (restore before returning!)
    return sum_exists

      


      
      

        

          
Deck 5: Recursive Complexity, Accumulators & Strict Grading Rules

          5 - Recursive Complexity and Backtracking 2
        

        

          

            
Tree O(2^n) vs. Accumulator O(n)

            

              Naive fib(n-1) + fib(n-2) is O(2^n). Passing accumulators forward in additive_sequence(n - 1, t1, t0 + t1) runs in strict O(n)!
            

          

          

            
Permutations Trap: O(n · n!) vs O(n!)

            

              get_permutations1 loops for sub in perms: taking O(n · n!). get_permutations2 passes current_perm + letters[i] forward and calls updated_set.update(perms) for O(n!) calls.
